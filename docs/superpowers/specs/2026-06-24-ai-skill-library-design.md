# AI 测试 Skill 库设计文档

## 1. 背景

当前 `AI测试` 页面以 `API测试 / UI测试 / 功能测试` 作为第一层分类，这种结构适合按任务类型浏览，但不适合承接“项目级 AI 资产”。

本次设计新增的 `Skill` 库被定义为：

- 项目内私有资产
- 面向 AI 测试场景长期复用
- 独立于单次生成任务存在

因此，`Skill` 不应继续作为某个任务页里的附属功能，也不适合放入 `基础服务` 这类平台连接配置模块中，而应成为 `AI测试` 下的核心二级入口。

## 2. 设计目标

本次调整的目标如下：

- 让用户理解 `Skill` 是“当前项目的 AI 资产”
- 让 `AI测试` 同时承载“资产沉淀”和“任务执行”两类能力
- 避免把 `Skill` 与 `API / UI / 功能测试` 混放在同一概念层级
- 为后续扩展 `Prompt模板`、`知识库`、`样例集` 等 AI 资产预留结构

## 3. 核心结论

保留左侧一级导航 `AI测试`，但重构其内部信息架构：

- 第一层改为 `Skill库`、`生成任务`
- 第二层仅在 `生成任务` 下再区分 `API测试 / UI测试 / 功能测试`

新的结构如下：

```text
AI测试
  ├─ Skill库
  └─ 生成任务
      ├─ API测试
      ├─ UI测试
      └─ 功能测试
```

这一定义明确区分了两类对象：

- `Skill库` 是资产层
- `生成任务` 是消费层

## 4. 信息架构调整

### 4.1 一级导航

左侧导航保持不变，仍保留：

- 项目总览
- 测试
- AI测试
- 基础服务

本次不新增单独一级导航 `Skill库`，避免用户误认为这是平台级公共能力。

### 4.2 AI 测试首页

`AI测试` 首页调整为工作台首页，而不是直接显示任务分类标签。

首页展示两个主入口：

- `Skill库`
- `生成任务`

推荐实现方式：

- 桌面端使用两个较强视觉分区的卡片入口，配合摘要数据
- 同时保留页内二级切换，避免用户每次进入都必须重复点卡片

入口摘要建议包含：

- `Skill库`
  - Skill 总数
  - 最近更新时间
  - 最近使用的 Skill
- `生成任务`
  - 各任务类型数量
  - 进行中任务数
  - 最近运行记录

### 4.3 Skill 库页

路由建议：

- `/ai-testing/skills`

页面职责：

- 查看当前项目下的 Skill 列表
- 按分类、状态、更新时间筛选 Skill
- 创建 Skill
- 编辑 Skill
- 删除 Skill
- 查看 Skill 详情
- 查看 Skill 被哪些 AI 任务引用

列表字段建议优先包含：

- Skill 名称
- 简介
- 分类
- 最近更新时间
- 最近使用时间
- 引用次数
- 状态

### 4.4 生成任务页

路由建议：

- `/ai-testing/tasks`

页面本身作为任务层容器，内部继续使用标签或分段切换：

- `API测试`
- `UI测试`
- `功能测试`

对应子路由可选两种方案：

方案 A，保留查询参数：

- `/ai-testing/tasks?tab=api`
- `/ai-testing/tasks?tab=ui`
- `/ai-testing/tasks?tab=functional`

方案 B，改为显式子路由：

- `/ai-testing/tasks/api`
- `/ai-testing/tasks/ui`
- `/ai-testing/tasks/functional`

推荐优先采用方案 A，以减少首轮改造成本，并复用当前页签切换模式。

## 5. 用户路径

### 5.1 资产沉淀路径

```text
选择当前项目
  -> 进入 AI测试
  -> 进入 Skill库
  -> 新建或维护 Skill
```

这是 `Skill` 的主路径，承担“统一管理”和“长期沉淀”的职责。

### 5.2 任务消费路径

```text
选择当前项目
  -> 进入 AI测试
  -> 进入 生成任务
  -> 选择 API / UI / 功能测试
  -> 创建或运行任务
  -> 选择一个或多个 Skill
```

这是 `Skill` 的消费路径，承担“在任务执行时引用项目资产”的职责。

### 5.3 任务内快捷路径

在任务页和任务详情页补充快捷入口：

- `选择 Skill`
- `管理 Skill`
- `跳转到 Skill库`

这样用户在边做任务时不需要绕回首页重新找入口。

## 6. 页面关系与跳转规则

### 6.1 AI 测试首页

首页进入规则建议如下：

- 用户点击左侧 `AI测试` 时，默认进入 `AI测试` 首页
- 首页展示 `Skill库` 与 `生成任务` 两个入口
- 用户上次访问记录可以作为次级优化，但首版不依赖

### 6.2 深链访问

需要支持以下直接访问方式：

- 从其他页面直接打开 `Skill库`
- 从任务详情直接跳回 `Skill库`
- 从 `Skill库` 进入某个 Skill 详情

因此 `Skill库` 必须拥有独立路由，不能只做成一个纯页内弹层。

### 6.3 项目上下文

`Skill库` 依然使用当前顶部项目选择器作为上下文边界：

- 未选择项目时不可创建 Skill
- 切换项目后只展示当前项目下的 Skill
- 不提供跨项目共享视图

这与“项目内私有资产”的边界保持一致。

## 7. 交互建议

### 7.1 Skill 库首页

推荐布局：

- 顶部：页面标题、说明、创建按钮
- 中部：筛选区
- 主体：列表或卡片表格
- 右侧或弹层：Skill 详情预览

如果当前项目下 Skill 较少，建议默认用卡片视图；当字段和操作增多时，可切换为表格视图。

### 7.2 任务页中引用 Skill

在创建任务或运行任务时增加独立的 `Skill` 选择区域：

- 支持搜索当前项目下 Skill
- 支持查看 Skill 简介
- 支持快速预览 Skill 内容摘要
- 支持从当前弹窗跳转到 `Skill库`

首版不要求在任务页里直接创建完整 Skill，避免任务页承担过多资产维护职责。

### 7.3 空态表达

当项目下还没有 Skill 时：

- `Skill库` 页面明确提示“当前项目还没有可复用 Skill”
- `生成任务` 页面在需要 Skill 的位置提示“先前往 Skill库 创建”

空态要把资产建设和任务消费关系讲清楚，而不是只显示空列表。

## 8. 对现有结构的影响

### 8.1 `AI测试` 模块

需要从当前“按任务类型平铺”的结构，改为“资产入口 + 任务入口”的结构。

意味着现有 `AiTestingPage` 的职责会变化：

- 现在：直接承载 `API / UI / 功能测试` 切换
- 调整后：先承载 `Skill库 / 生成任务` 切换，再由 `生成任务` 承载任务类型切换

### 8.2 现有任务页面

现有 API 生成任务详情和功能生成任务详情整体可继续保留，但入口与上级面包屑需要改造：

- 从“AI测试 / API测试”语义
- 改为“AI测试 / 生成任务 / API测试”

### 8.3 文案与认知

页面文案要统一使用以下语义：

- `Skill库`
- `生成任务`
- `项目级 AI 资产`

避免混用“能力库”“模板库”“服务配置”等词，否则会弱化定位。

## 9. 非目标

本次设计不包含以下范围：

- 跨项目共享 Skill
- 全局公共 Skill 市场
- Skill 版本治理细节
- Skill 发布审批流程
- Skill 与基础服务配置合并
- Skill 后端真实接口接入

这些能力如果未来要做，应建立在“项目内 Skill 库”已经稳定后再扩展。

## 10. 分阶段落地建议

### 阶段 1：结构改造

- 重构 `AI测试` 首页层级
- 新增 `Skill库` 入口与独立页面
- `Skill` 相关接口先只做前端占位，不接真实后端
- 保留现有 `生成任务` 三分类内容
- 在任务页增加 `选择 Skill` / `管理 Skill` 的快捷入口占位

### 阶段 2：资产联动

- 后端接口准备完成后，再接入 `Skill` 列表、详情、创建、编辑、删除能力
- 任务创建与运行流程接入 Skill 选择
- 在 Skill 详情中展示引用关系
- 增加最近使用、引用次数等辅助信息

## 10.1 接口占位原则

在后端接口未准备完成前，`Skill库` 页面按“可接入骨架”建设，原则如下：

- 不依赖前端硬编码 mock 业务数据
- 可以保留静态空态、字段骨架、操作入口和禁用态按钮
- 可以预留统一的 `api` 方法签名与类型定义，但实际请求逻辑先返回占位结果或不触发请求
- 页面文案需要明确标识“等待后端接入”
- 后续接入真实接口时，应避免推翻现有路由、页面层级和交互结构

### 阶段 3：资产扩展

- 在 `AI测试` 资产层继续扩展其他可复用对象
- 如 `Prompt模板`、`知识库`、`样例集`

## 11. 验收标准

完成本次设计后的产品结构，应满足以下判断标准：

- 用户能在 1 次进入 `AI测试` 后理解“Skill 是项目资产”
- 用户不会把 `Skill库` 误解为基础服务配置
- 用户不会把 `Skill库` 与 `API / UI / 功能测试` 视为同级业务场景
- 用户既能从 `AI测试` 主入口统一管理 Skill，也能在任务页顺手使用 Skill

## 12. 最终结论

`Skill库` 的最佳位置是 `AI测试` 下的核心二级入口，但不应与 `API测试 / UI测试 / 功能测试` 并列，而应与 `生成任务` 并列。

最终推荐结构为：

```text
左侧一级导航：AI测试

AI测试首页：
- Skill库
- 生成任务

生成任务下再分：
- API测试
- UI测试
- 功能测试
```

这套结构同时满足了：

- `Skill` 是项目级 AI 资产
- `Skill` 主入口位于 AI 测试域内
- 现有任务能力可以平滑迁移
- 后续 AI 资产扩展仍有足够空间
